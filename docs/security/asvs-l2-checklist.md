# OWASP ASVS 5.0 Level 2 checklist

Zelvo targets OWASP ASVS **Level 2** for every tenant (non-functional requirement "Security standard"). This checklist was started in task A5 and is completed in task F7 (ASVS L2 review before the external penetration test). Every task that touches a listed area updates its rows.

- Standard: [OWASP ASVS 5.0.0](https://github.com/OWASP/ASVS/tree/v5.0.0/5.0) (May 2025), levels 1 and 2: 253 requirements. Requirement texts are in the standard (CC BY-SA 4.0) and are not copied here; look them up by ID.
- Status: **Met** (with evidence), **Partly met**, **Open** (with the task expected to close it), **Not applicable**, **Not assessed** (not reviewed yet).
- Evidence points to code, tests, architecture notes and build plan tasks (A1-F7 in `docs/phase1-build-plan.md`).

**Summary (2026-11-27, review completed in F7, with F6 merged; M1, K1, K4, J1, M2):** Met: 182 · Partly met: 41 · Open: 5 · Not applicable: 25 · Not assessed: 0.

Every requirement has now been reviewed against the code (task F7, before the external penetration test). F7 fixed what could be fixed without a product decision or the hardened install: a Content-Security-Policy with a nonce on every page and HSTS at the proxy (V3.4); Keycloak events for sign-ins and failures and refused API calls as security events in the audit log (V16.3); disabled people turned off in Keycloak with their sessions ended, and administrators ending sessions (V7.4); notification email without a plain-text fallback (V12.1.1); no TRACE (V13.4.4); `no-store` on API answers (V14.3.2); email-code limits (V6.5.5); two race conditions (V2.3); and the missing inventories (cryptography, communications, logs, data protection levels, components: V11.1, V13.1.1, V16.1.1, V14.1, V15.1).

Still open, for the product owner: a common-password blocklist and its source list (V6.2.4, L1), context-specific words (V6.1.2, V6.2.11), a breached-password check (V6.2.12) and a limit on parallel sessions (V7.1.2). Task M1 gave the Helm chart's Caddyfile the same HSTS and TRACE refusal (V3.4.1, V13.4.4 now met), checked in CI. Partly met transport and configuration rows after the hardened install (F6): TLS for the Keycloak back channel, the API behind the proxy and the OTLP collector (V12.3), service passwords as environment values rather than a secrets manager (V13.3.1), separate Valkey users and network egress limits (V13.2). Other partly met rows name their remaining gap in the row.
